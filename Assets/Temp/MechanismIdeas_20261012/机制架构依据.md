# TapTap 机制架构与组合依据

当前玩法围绕两个可运动实体和一个角色状态机展开。最有价值的组合接口是角色形态、头身位置、接触方向、全局虚实状态、当前复活点，以及持续运动的时间过程。关卡只是这些接口的空间编排，不必引入新的机关脚本就能产生不同用途。

## 代码如何组织玩法

| 层 | 主要代码 | 对设计的意义 |
| --- | --- | --- |
| 角色输入与状态 | PlayerInput、PlayerController、PlayerConfig | 左右移动与空格的按下松开边沿，决定合体、伸头、悬停、收头、分离、吸附、拾取阶段 |
| 运动与碰撞 | MovableEntity、KinematicMotor2D、CollisionQuery2D、GroundSupportQuery2D | 头身独立运动；实体阻挡、单向平台、传送带支撑与接触方向决定动作结果 |
| 世界机关 | WorldSurface、SpringPad、MechanismSwitch、WorldPhaseState、PhaseBlock | 地面运动、弹起、全局状态翻转和实化挤出共享同一角色与实体系统 |
| 死亡与历史 | RespawnService、RewindManager、SceneResetManager | 死亡可只返回一半；回溯恢复全部已记录玩法状态；R重新加载场景 |
| 空间资源 | LevelDefinition、LevelPlacement、LevelBrush、LevelPalette、LevelRegion | 逐格笔刷、分层配置、入口旗帜与测试批注构成独立关卡布局 |
| 地图与展示 | WorldMapDefinition、WorldMapPrefabBuilder、LevelSceneRuntime、DemoCamera | 多模块可以在一个场景并存；镜头与逻辑运行范围并不相同 |

核心状态转换可概括为：合体 → 伸头 → 悬停 → 收头；收头无阻挡回到合体，有支撑阻挡则进入分离。分离后可选择吸附、侧面拾取、从上方踩头，或者让头从上方落到身体。只有吸附成功合体才使用普通或远距离跃起；普通收头和侧面拾取没有这个奖励。

RewindManager集中驱动固定步模拟，先推进复活与实体准备，再模拟角色和其他实体，随后处理按钮并提交运动。按钮能够检查本步的运动片段，快速经过感应区也可能触发。不要只按步末位置理解机关输入。

## 本包采用的实际参数

来源是现有 `Assets/Runtime/Config/PrototypePlayer.asset`，不是 PlayerConfig 字段默认值或旧设计说明。

| 参数 | 实际值 | 设计影响 |
| --- | --- | --- |
| UnitSize | 1 | 草图一格为一个世界单位 |
| MoveSpeed | 4格每秒 | 主动水平移动与传送带速度相加 |
| Gravity | 24格每秒平方 | 所有弹起和下落时间需配合此值 |
| JoinedOffset | 0.75格 | 头身位置基准之间的距离 |
| MaxExtension | 3.4格 | 在合体间距之外额外伸出的距离 |
| ExtensionDuration | 0.45秒 | 提前松开会等待伸头结束或受阻后收头 |
| RetractionDuration | 0.25秒 | 收头过程中暂停左右输入 |
| AlignmentTolerance | 0.35格 | 吸附允许的最大水平误差 |
| DistantThreshold | 7格 | 启动时位置Y差严格大于7，才选择远距跃起 |
| NormalLaunchHeight | 1.1格 | 普通吸附成功后的总跃起高度 |
| DistantLaunchHeight | 3.4格 | 远距吸附成功后的总跃起高度，替代普通高度 |
| SpringHeight | 4.5格 | 从上方踩散落头产生的弹起高度 |
| RecallCooldown | 0.22秒 | 松空格尝试后，短时间内最多缓存一次新的操作 |
| PickupDuration | 0.24秒 | 横向拾取时头平滑跟随身体回到合体位置 |
| DeathBoundary | 世界Y小于负15 | 不是相对关卡底部的距离 |

玩家Prefab身体碰撞尺寸0.7×0.9格，头为0.7×0.6格，偏移为零时合体包围高度约1.5格。场景里的普通SpringPad默认Height为3格，不跟随踩头的4.5格参数。本包传送带使用每格配置Speed=1.25，正值向右。

## 需要保留的机制边界

按钮不是持续压力开关。头或身体进入都会翻转，持续占用不重复触发，离开不自动关门。它以所有实体接触的逻辑或作为占用，默认重新触发间隔为0.18秒；若在冷却期间重新进入并一直占用，冷却结束不会补发一次翻转。

引导线变蓝只检查头身对齐、上下关系和返回状态，不提前检查整条吸附通路。BeginPull保存当时头位置作为目标；吸附阶段不推进头的自由运动。实体带面与普通实块会阻挡身体上升，不能把所有传送带当成单向平台。

只有Detached才是独立返回两半的形态。Extending、Holding、Retracting、Pulling、PickingUp都被HasMagneticConnection视为连接，一半死亡会触发头身一起返回。头部独立死亡不会让身体自动飞回来，也不会直接自动合体。

只有身体触碰旗帜会设置复活点。返回旅程在开始时保存目的地，本次飞行途中刷新旗帜不会改写已有目的地。死亡返回过程中无碰撞，也不参与按钮占用；返回不能当成一条会触发沿途按钮的物理飞行路径。

实化挤出要有可用候选。当前实现扩展相连实块的占据范围，按候选位移长度排序并检查目的地和路径；不保证向上，不保证等距时固定方向，也不保证在所有方向被堵住时解决重叠。S13因此保留为实验。

视野外的活跃对象照常模拟，但当前固定区域镜头没有自动切换房间的逻辑。WorldMapPassage是地图中的通行箭头与注释，没有运行时传送器。LevelEndpoint目前仅保存位置与标识，不触发通关。S12利用同场景的因果关系，分房镜头仍需编排。

回溯恢复位置、速度、形态、全局虚实、按钮占用冷却、旗帜地址及返回任务。它不会留下旧未来的实体或持续开的门。R会重新加载并清空历史；它与分体死亡保留世界状态的作用不同。
