# TapTap 机制组合灵感包

16个场景探索现有机制的交叉用途，每个场景包含一道局部谜题、布局示意、探索路线、输入输出对照、思考点和变形方向。内容面向筛选灵感与小规模机制验证，观察目标不要求组成完整关卡。

- [交互浏览器](index.html)：按机制、关键词或建议顺序筛选场景，查看布局和输入输出。
- [关卡组合创意](关卡组合创意.md)：完整场景卡与六种继续拼接的方向。
- [机制架构依据](机制架构依据.md)：代码结构、实际配置、机制边界和组合矩阵。
- `Layouts/TEMP_S01.asset` 到 `Layouts/TEMP_S16.asset`：沿用现有笔刷的独立 LevelDefinition 布局，包含入口旗帜和谜面测试批注。
- `Diagrams` 保存布局示意，`Data/scenes.json` 保存结构化场景数据，`Tools/build_ideas.py` 可重新生成本包内容。

所有新内容都位于 `Assets/TEMP/MechanismIdeas_20261012`，Windows 下该目录的实际大小写可能显示为 `Assets/Temp`。它独立于现有关卡、Prefab和世界地图目录，也不属于项目根目录的 Unity `Temp` 缓存。

## 在 Unity 中查看和验证

1. 等待 Unity 导入资源和编译完成，双击 `Layouts` 中的布局，在现有关卡编辑器查看和调整。
2. 在 Project 中选择本包一个或多个布局，执行 **TapTap → TEMP Inspiration → Generate Selected Test Scenes**。也可用 **Generate All Test Scenes** 为整个包生成测试资源。
3. 本包提供的菜单只将区域Prefab和测试场景写到本包的 `Prefabs` 与 `Scenes` 子目录，复用已有玩家、Runtime、笔刷和配置。它不会向正式关卡目录创建资源。
4. 打开生成的场景，Play，按谜面中的输入输出逐项观察。靠近入口附近的批注可以按 E 记录体验，评价回写本包布局。

现有关卡编辑器内置的“一键生成测试场景”默认写入 `Assets/Scenes/Test`；验证这些草图时使用上述 TEMP 菜单，以保持输出路径独立。头的存放、带尾接头和按钮时序需要按实际碰撞体微调。S12的分房镜头、S13的挤出方向、S14的分支路线尤其适合先做局部验证。

## 建议先看哪些组合

- S01 隔层遥控：头触发高处按钮，身体使用下层通路。
- S06 只寄回头：身体先设置地址，头死亡后独立返回。
- S09 先下去才能跳得更高：主动扩大吸附距离换取更高跃起。
- S10 不要让按钮空出来：头与身体连续占用接力，避免再次翻转。
- S15 让弹簧替身体按按钮：用头的周期运动制造远程输入。
- S16 低顶给头设定高度：实体阻挡为本次伸头动作设定悬停高度。

## 验证范围

生成时检查了布局边界、同层格子冲突、入口引用、托管配置类型和现有笔刷GUID。每张卡明确列出了需要Play验证的空间条件；这里没有把“代码允许的交互”标成“已经通关的谜题”。终点是现有的观察占位标记，不自动判定通关。

Python生成器再次运行会覆盖本包的生成布局、图和场景文档。已在Unity里调整过的布局如需保留，先在本包内另存一份再运行生成器。
