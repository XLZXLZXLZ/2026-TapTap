1. 基础设计

游戏玩法为2D平台类游戏，核心玩法模块为控制角色上下身分离与合并这一基础规则，与地形和其它机制产生各式各样的交互规则产生的玩法机制涌现形式。游戏中场景构建以单位格为基准。单位长度是一个可定义的数字，适配美术最终设定的单格长。目前阶段，1单位长度 = 游戏世界距离的1.



2. 基础操控

角色控制提供三个键位操作：左，右，空格；R 键用于重新开始当前场景；长按 Z 回溯，松开 Z 从当前状态继续。

点按左/右 Ctrl 切换子弹时间：开启时游戏时间流速为 0.5，屏幕以 0.20 秒淡入轻微淡蓝色遮罩；再次点按恢复之前的正常/调试倍速并淡出。合体的短暂慢动作相对该流速叠加；暂停、反馈、回溯和转场期间不响应 Ctrl，切换场景后关闭子弹时间。

角色与分离头部自然到达上升最高点或向上撞顶后，最初 0.10 秒下降使用 65% 重力，然后恢复正常重力。上升阶段和起跳速度保持原有规则；头身独立计算缓冲，计时支持回溯，复活及传送清除缓冲。Player Configuration 中可调整“下降缓冲时长”和“缓冲期间重力倍率”，时长设为 0 可关闭。

调试时按 I 切换游戏时间流速，依次为 1、2、4、8 倍并循环，HUD 显示当前倍速。倍速在本次游玩中保留，重新启动 Play 恢复 1 倍；暂停、反馈窗口、回溯及转场期间不会被该操作打断。按 O 可统一停用或重新启用所有出口。

回溯仅用于试错撤销。按固定模拟步保存各动态对象的玩法状态，按需分块追加记录，保留本次关卡从记录开始以来的全部历史，不设固定时长上限；到达最早记录时停住。头身及其他参与回溯的对象位置与玩法状态连续 10 秒模拟时间完全不变，且没有进行中的动作、冷却或复活任务时，停止追加历史；模拟继续，仅更新最后一个快照。任意位置或玩法状态变化时，当步恢复追加记录，保留此前历史，回溯直接跨过省略的等待时间。静止判定使用精确位置比较，最初 10 秒静止仍正常保留。松开 Z 后释放被放弃的未来记录，重新记录新的尝试，并重新计算静止时间。角色形态、头身位置与速度、机关虚实、按钮占用与冷却、复活点及复活任务都会恢复；弹簧压缩、角色挤压、粒子和震屏等短暂视觉效果不记录。R 重载场景后清空回溯历史。记录保存在内存中，随实际记录时长增长，清空历史时释放对应存储。

连续按住 Z 时，回溯速度默认在 5 秒真实时间内从 1.5 倍线性提升至 3 倍；松开后重新按住从起始速度开始。`GameplayRuntime` 的 `Managers/RewindManager` 可调节起始倍速、最大倍速和加速时长（0 秒表示立即使用最大倍速）。回溯采用相机全屏 Shader 表现轻度降饱和度、间歇横向撕裂、局部色差、扫描线、颗粒和暗角，由同一对象的 `EffectManager` 调节强度与淡入淡出。到达历史起点时动态干扰减弱；松开 Z 当帧恢复操作，画面效果独立淡出。HUD 与黑屏遮罩不经过该后处理，视觉状态不进入历史快照。

回溯的时间方向通过向上倒扫的亮带、向内收拢的边缘波纹、角落向左流动的倒带箭纹，以及青色/紫色的时间残影体现。残影默认每 0.055 秒采样一次，仅保留两张半分辨率原始画面，突出移动或变化的亮部，不叠加处理后的画面。松开 Z、再次开始回溯、相机禁用或分辨率变化时清空残影，避免跨尝试、跨场景残留；上述视觉参数均可在 `EffectManager` 中调节。

边缘波纹默认幅度为 0.002，变化速度为 4，降低画面波动；分别由 `EffectManager` 的 `rewindEdgeRipple` 和 `rewindEdgeRippleSpeed` 调节。

角色形态：高度约1.7长度，其中上/下半身均为约0.8单位长度，中间保留较小空间。

左右控制角色的移动，空格控制玩家的头身分离操作。





3. 基本地形与头身分离操作规则

当玩家头身在一起时

[按住空格]——将头部向上弹出至多4.4个单位高度（缓出曲线），并使用一根磁力线条连接，长按期间，脑袋会跟随人物移动。

头部弹出时，角色播放短暂的视觉缩放动画，上升期间暂停左右操控，重力和正常碰撞仍然生效。头部到达最大伸出高度，或提前被墙体阻挡停止上升后，恢复左右操控；受阻时播放一次轻微相机震动。缩放不改变碰撞体。

[松开空格]——头部首先向下缩回（缓入曲线），根据路径上触碰到的物体，产生不同的后续交互。

头部收回期间同样暂停左右操控，重力和正常碰撞仍然生效；收回完成并合体，或受地形阻挡停止收回并分离后，恢复左右操控。

游戏中最常见的两类物体：普通墙体和单向平台

1） 当头部上升时，触碰到单向平台：头部正常从下往上穿过平台

2） 当头部上升时，触碰到墙体：头部停止上升并悬停在当前高度，即使之后移动使头部上方不再有平台，也不会继续升高。

3） 当头部向下收回时，触碰到单向平台/墙体：头部停止下降并留在接触位置，立即头身分离，不自动将下方的身体向上吸附。吸附需要在分离后再次操作空格触发。

4） 如果收头路径没有地形阻挡：头部正常缩回并与身体重新连接，不执行吸附，也不额外跃起。



当玩家头身分离时

此时头部留在原地，只有下身可以进行移动。

[按下空格]——若此时已经符合吸附条件且冷却结束，立即开始现有的吸附动作，无需等待松开；保留对齐、上升动画与合体跃起，不瞬移合体。横向对齐容差由 0.35 格略增至 0.40 格，身体必须仍在头部下方，地形阻挡判定不放宽。若未符合条件，则按住期间仍淡入竖直向下的引导线：可吸附时为蓝，并在身体高度停止；不可吸附时为红，向下延伸。

[松开空格]——尚未开始吸附时，按松开这一刻的对齐状态再尝试；若不符合，引导线红着额外显示一小会后淡出。已在按下时开始吸附则不会因松开再次触发。每次尝试后仍有短暂冷却，冷却期间最多缓存一次预输入；冷却结束时已对齐可直接执行，否则继续保留松开尝试的流程。

若吸附成功：

1）玩家初始若在头部下方5单位长度以内，则将下方的身体向头部吸附（缓入曲线）。

2）若玩家初始在头部下方5单位长度更远的地方，则玩家在吸附上头部时会额外跃起1格（想象一个强大的冲击力）

吸附过程中，如果身体在上升时触碰到了墙体，则结束吸附，保持头身分离。

如果身体成功接触到了头部，则会重新连接，并在接上时额外提供一个1格左右的向上速度以保证能跳跃上平台；远距离吸附沿用上述额外跃起规则。



散落的头部还有可能与玩家有其它交互

1）若头部从上方落到玩家身上（例如传送带），玩家会身体（y轴变小x轴放大地）放缩表现出向下冲击力并重新超级拼装。此时若玩家站在单向平台上，那么会被砸下去。（如同传统2D平台游戏中，在单向平台上按↓那般）只穿过触发时脚下的一个平台，下方其他平台仍正常阻挡；头身完全穿过目标平台后恢复对它的碰撞。空中合体不会忽略尚未落到的平台，实体墙体或地面也不会被穿过。

2）若身体从同高处横向经过并接触头部，先检查身体上方的合体空间；空间被实体地形阻挡时保持头身分离。空间允许时立即完成逻辑合体，移动使用完整的头身碰撞范围，不额外弹起。只有头部外观平滑飞到身体上方，动画中跟随身体移动，不单独参与碰撞；向墙体移动会被合体碰撞范围挡住，不会中断归位动画。回溯恢复动画进度。

3）只有身体从上方走到或落到头部上，才会把头部当成弹簧并向上弹起3格。任意其它可运动实体从上方踩到散落头部时同样弹起3格；侧面或下方接触不会触发弹跳。头部同时播放简单的缩放Tween：先x变大、y变小，再x变小、y变大，最后恢复原始比例。缩放仅作用于视觉，不改变碰撞体。



4. 其它机制

主要用于辅助探索头身分离的可挖掘机制的系统。

1） 传送带，玩家，头，以及任意其它可运动实体，在开启的传送带上都会被朝着其运动方向推进。

2） 虚化/实化平台，游戏中有按钮开关，触发后所有虚化/实化平台状态对调。

3） 复活点。复活点以一面小旗帜作为标识，通常在区域出生点附近。当前区域直接决定复活点，触碰旗帜不再更新复活点。当玩家以任意形式死亡时，若此时头身在一起，会播放死亡特效并变为拖尾飞回当前区域复活点；若头身已分离，沿用原有分体复活逻辑。复活不会重置场景。身体死亡返回期间保持当前区域，返回路径不会触发切区或发现其他区域。

// 原先通过躲开旗帜保留旧复活点的元谜题思路已过时；复活点现在始终取当前区域的入口。

4）跨区域。所有关卡都在同一个游玩场景中，身体可以连续移动到另一关卡。以身体碰撞中心判断区域，默认保留 0.12 格边界缓冲，头部单独跨区不切镜头。每关在关卡 SO 中预配置固定透视镜头，记录区域局部位姿与 FOV，或毫米焦距及传感器等物理镜头参数。区域变化时平滑过渡位置、旋转和镜头参数，不暂停操作、不重置头身、机关或回溯历史。首次进入及回溯切区直接还原目标镜头。

本次运行中尚未进入的区域关闭 Renderer 绘制，保留原材质，碰撞与逻辑持续运行；首次进入时立即显示，此后在本次运行中持续可见，离开或回溯不会隐藏。表现入口保留在 `RegionRevealView.ApplyVisibility`，后续可替换显隐效果。发现状态只保存在运行时内存，不写入存档。重置整个世界或重新进入游玩场景时，清空发现状态，仅当前入口区域立即可见，其余区域重新隐藏；通关与选关解锁进度独立保留。发现区域同时解锁选关，但不计作通关。相机按本关固定预设取景，已经发现的相邻区域可以入镜。不处理区域之间的空白；发生短暂越界时保留当前区域。

新增完整一格的方形平台：外形和碰撞体均为正方形，碰撞规则与普通单向平台一致。`SquarePlatform` 预留头部完整向上穿过、从上方落到平台的 C# 事件与 Inspector 事件接口；本阶段只提供通知接口，不播放动画。

不在视野范围内及尚未发现区域中的物体依旧正常运作逻辑。大世界的兜底死亡线按整个世界最低边界加配置偏移计算，允许正常进入负坐标区域。

退出进行选关，或选择重新开始按钮，则会真正刷新场景（重新出生在该场景的出生点上）

按 R 键也会重新加载当前场景：画面先淡出至全黑，在黑屏下加载场景，加载完成后再淡入恢复画面。玩家、复活点与场景机制恢复为场景初始状态；过渡期间重复按 R 不会重复触发重载。

# 回溯阶段

在游戏后期，玩家在第20关第三个触发点正式进入回溯阶段，连续跨区域进入第19关拾取钥匙，再穿越一系列场景回到第一关打开一扇门。拾取钥匙不再作为进入回溯阶段的触发点。

进入回溯阶段时，会发出一次事件通知，所有需要信息的物体监听它并更新逻辑。



// 下文中所有"回溯"指的都是从最后一关走回第一关这个长流程，不是游戏中按Z的撤回操作。



## 回溯阶段表现：

在回溯阶段，游戏会附加一个变暗滤镜（最大值微弱即可），和一个轻微色散和撕裂滤镜。

游戏会额外附加一些光贴图引导（现在在地图编辑器里配置的那些，原先的"拾取钥匙后打开"的字段不再需要），它们全部在进入回溯阶段时淡入。



### 1. 准备阶段

在进入20关时，游戏会进入一个演出。在三个Trigger2D处，执行以下操作。

准备一个特殊平台预制体，它的view高度会比碰撞盒高一格，用于演出。

前两个会使场景轻微闪暗2次再恢复正常，第三个则会真正变暗，同时镜头震动，特殊平台播放一个粒子爆炸效果的同时，view掉落到真正碰撞盒位置，微微倾斜（形成掉落卡住的感觉）。

从第三个开始，游戏正式进入回溯阶段。（现在的游戏临时代码是拾取钥匙时进入，我们需要提前至这个时间点。）



### 2. 正式阶段

掉落卡住的平台由于低一格，会引导玩家只能跨场景进入19关，在此处会先有一个trigger2D，进行一个收音机演出。

然后玩家将遇见摆放的钥匙并拾取它。当前代码是将钥匙直接销毁并播放粒子，我们需要修改它。

拾取后，改为播放另一个更弱的粒子，并且钥匙将持续平滑跟随玩家body部分的身后略微偏上的位置，伴随有轻微浮动。

在拾取钥匙时，强制暂停一回，将PausePanel左侧的角色图像替换为另一图像（可以预先隐藏在预制体中，到了时间再作替换）

至此出发演出结束，玩家携带钥匙继续返程。回溯阶段已在第20关第三个触发点开启，R 从该触发点开始禁用。进入返程、拾取钥匙动画完成、开门完成时分别清空 Z 历史并建立新的撤回起点。



### 3. 回溯变化

游戏中所有的录音机（暂未实现）都会播放两套预设语音内容，一套为普通流程时的语音，另一套为回溯语音，它们订阅阶段切换事件。

其中第19关的录音机最特殊，它还会在回溯时额外进行一个演出（见2）



### 4. 最终阶段

玩家将穿过整个场景最终回到第一关左上角。我们需要一格机关门，它仅在玩家进入附近trigger范围时且身上有钥匙时，将钥匙移动到它身上，随后钥匙爆出粒子（原先的拾取粒子）消失，门打开，玩家可以向左走以到达最终路径。



### 5. 前往结局

游戏中已有22号场景前往结局的撤离演出。

返程增量的预制体配置、状态事件与独立预览见 `Assets/C# Scripts/World/ReturnJourney/README.md`。拾取钥匙保留完整放大与时缓，动画结束后打开暂停面板，待面板入场后以强撕裂过渡切换左图为 `Assets/Art/UI/RobotLevelBlueprint.png`。广播及第19关录音机演出本次暂缓。
